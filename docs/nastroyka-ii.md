# Как подключить агента к разным ИИ

Правила агента лежат в обычных текстовых файлах и от модели не зависят:

| Файл                            | Зачем                                                           |
| ------------------------------- | --------------------------------------------------------------- |
| `AGENTS.md`                     | Полные правила и порядок работы. Главный файл                   |
| `prompts/system-prompt.md`      | Короткая выжимка правил для поля «инструкции» в чат-интерфейсах |
| `prompts/zapros.md`             | Текст запроса на подготовку дайджеста                           |
| `templates/daydzhest.md`        | Шаблон черновика: текст, метки, трассировка                     |
| `templates/daydzhest.pptx`      | Шаблон итогового файла АФТ                                      |
| `nastroyki/kontakty.md`         | Контакты координаторов для второй страницы                      |
| `nastroyki/rabochie-gruppy.md`  | Рабочие группы                                                  |
| `nastroyki/istochniki.md`       | Образец перечня облачных папок и сервисов встреч                |
| `nastroyki/dorozhnaya-karta.md` | Инициативы дорожной карты                                       |
| `scripts/proverka.py`           | Формальная проверка черновика                                   |
| `scripts/sborka.py`             | Сборка итогового файла .pptx из черновика                       |
| `scripts/zapusk.py`             | Запуск через API любой модели с форматом OpenAI                 |

Перед началом заполните `nastroyki/rabochie-gruppy.md`, `nastroyki/dorozhnaya-karta.md` и перечень источников `workspace/istochniki.md` (раздел «Облачные источники»).

## Важно до начала работы

- Внутренние документы АФТ передаются во внешний ИИ только по правилам информационной безопасности вашей организации. Если правила запрещают внешние сервисы, используйте локальную модель (раздел 5).
- Поле инструкций в чат-интерфейсах ограничено по длине. Поэтому в него вставляется короткий `prompts/system-prompt.md`, а полные правила (`AGENTS.md`) загружаются файлом.
- Результат: два файла. Черновик `…_черновик.md` с метками и служебной частью и итоговый файл `….pptx` по шаблону АФТ без меток.
- Если ИИ не умеет запускать скрипты, он выдаёт только черновик. Сохраните его в файл, затем проверьте и соберите итоговый файл сами:

  ```bash
  pip install python-pptx
  python3 scripts/proverka.py workspace/outputs/<файл>_черновик.md
  python3 scripts/sborka.py workspace/outputs/<файл>_черновик.md
  ```

- Если ИИ в чате умеет выполнять код (например, анализ данных в ChatGPT или Claude), приложите к чату `templates/daydzhest.pptx` и `scripts/sborka.py` и попросите собрать итоговый файл скриптом.

## 1. Чат с проектами или собственными ассистентами

Подходит для Claude (Проекты), ChatGPT (Проекты или собственные GPT) и других сервисов, где можно сохранить инструкции и файлы.

1. Создайте проект или ассистента, например «Дайджест ЦК ОПИ».
2. В поле инструкций вставьте текст `prompts/system-prompt.md`.
3. Загрузите в файлы проекта: `AGENTS.md`, `templates/daydzhest.md`, `nastroyki/rabochie-gruppy.md`, `nastroyki/dorozhnaya-karta.md` и свой перечень источников `istochniki.md`. Если ИИ умеет выполнять код, добавьте `templates/daydzhest.pptx`, `scripts/sborka.py`, `scripts/proverka.py` и заполненный файл контактов.
4. Если в сервисе есть коннектор к вашему облаку, подключите его по разделу «Облачные источники». Если нет, прикладывайте файлы к запросу.
5. Для каждого дайджеста откройте новый чат в проекте, вставьте запрос из `prompts/zapros.md` и приложите материалы за период.
6. Сохраните черновик в файл `ГГГГ-ММ-ДД_дайджест_<период>_черновик.md`, проверьте его и соберите итоговый файл (см. «Важно до начала работы»).

## 2. Чат без сохранённых инструкций

Подходит для DeepSeek, GigaChat, YandexGPT и любых других чатов.

1. Откройте новый чат.
2. Приложите файлы: `AGENTS.md`, `templates/daydzhest.md`, `nastroyki/rabochie-gruppy.md`, `nastroyki/dorozhnaya-karta.md` и материалы за период.
3. Первым сообщением вставьте текст `prompts/system-prompt.md`, затем запрос из `prompts/zapros.md`.
4. Если чат не принимает файлы, вставьте их текст в сообщение. Порядок тот же: правила, шаблон, настройки, материалы.
5. Сохраните черновик в файл, проверьте его и соберите итоговый файл скриптами.

## 3. Агентные инструменты, которые работают с папкой репозитория

Подходит для Claude Code, Codex CLI и других инструментов, которые читают `AGENTS.md` из корня репозитория.

1. Клонируйте репозиторий и откройте его в инструменте.
2. Инструмент сам прочитает `AGENTS.md`. Claude Code читает `CLAUDE.md`, а он ссылается на `AGENTS.md`.
3. Заполните `workspace/istochniki.md`. Подключите облачные папки к инструменту только на чтение или выгрузите их в `workspace/inputs/<код источника>/` (раздел «Облачные источники»).
4. Дайте запрос из `prompts/zapros.md`. Инструмент сохранит черновик в `workspace/outputs/`, запустит `scripts/proverka.py` и соберёт итоговый файл `scripts/sborka.py`.

Если инструмент читает файл с другим именем, создайте его в корне с одной строкой: «Правила агента: AGENTS.md. Прочитай его перед работой».

## 4. Через API: скрипт `scripts/zapusk.py`

Подходит для провайдеров с форматом запросов OpenAI Chat Completions: OpenAI, DeepSeek, Anthropic в режиме совместимости, OpenRouter, YandexGPT, Ollama, LM Studio и другие. Для запроса к модели нужен только Python 3.8 или новее; для сборки итогового файла нужна `python-pptx` (`pip install python-pptx`).

1. Скопируйте `.env.example` в `.env` и заполните адрес API, ключ и имя модели. Адрес и имя модели сверьте с документацией провайдера.
2. Сохраните материалы за период как текст (`.md`, `.txt`) в `workspace/inputs/`.
3. Запустите:

   ```bash
   python3 scripts/zapusk.py --period "III квартал 2026" --data-sreza 05.10.2026 --imya 3кв-2026 workspace/inputs/*.md
   ```

4. Скрипт сохранит черновик в `workspace/outputs/`, проверит его и, если установлена `python-pptx`, соберёт итоговый файл .pptx.

Если провайдер требует другой заголовок авторизации, задайте `AI_AUTH_SCHEME` в `.env`. Если провайдер не поддерживает формат OpenAI, используйте чат (раздел 1 или 2).

## 5. Локальная модель

Документы не покидают компьютер.

1. Установите Ollama или LM Studio и загрузите модель, которая хорошо пишет по-русски и принимает длинный текст.
2. В `.env` укажите `AI_BASE_URL=http://localhost:11434/v1` (Ollama) или адрес LM Studio и имя модели. Ключ не нужен.
3. Запустите `scripts/zapusk.py` как в разделе 4.

Небольшие локальные модели хуже соблюдают правила. Проверяйте результат скриптом и вручную.

## Облачные источники

Материалы рабочих групп обычно лежат в облаке: Google Drive, Яндекс Диск, OneDrive, SharePoint, облако организации, сервис встреч с расшифровками. Агент работает с ними по `AGENTS.md`, п. 2.8: ищет только в перечисленных папках и ничего в них не меняет.

### Шаг 1. Перечень

Скопируйте `nastroyki/istochniki.md` в `workspace/istochniki.md` и заполните: код, сервис, адрес папки, что в ней лежит, к какой РГ относится, способ подключения. Файл в `workspace/` в git не попадает. В чат-сервисе загрузите его в файлы проекта или приложите к запросу.

### Шаг 2. Подключение

**Коннектор ИИ.** Подходит, если ИИ умеет сам читать ваше облако (например, коннекторы Google Drive, OneDrive, SharePoint в Claude и ChatGPT).

1. Перед подключением проверьте правила информационной безопасности организации: документы из облака уйдут поставщику ИИ.
2. Дайте доступ только к папкам из перечня. Если сервис позволяет, выберите доступ только на чтение. В агентных инструментах (Claude Code и подобных) запретите в настройках инструменты записи коннектора: создание, правку, удаление, открытие доступа.
3. Проверьте, что ИИ видит вложенные папки и общие диски: попросите его перечислить файлы одной папки и сверьте число с облаком.

**Выгрузка.** Подходит, если коннектора нет (например, для Яндекс Диска или облака организации) или правила ИБ запрещают коннектор.

1. Скачайте папку целиком и распакуйте в `workspace/inputs/<код источника>/`. Документы Google Docs, Sheets и Slides при скачивании становятся файлами .docx, .xlsx, .pptx.
2. Запишите дату выгрузки в колонку «Адрес» перечня: агент укажет её в ссылках.
3. Для регулярной выгрузки подойдёт [rclone](https://rclone.org): команда `copy` только читает облако и копирует файлы на компьютер.

   ```bash
   rclone copy "<имя подключения>:<путь к папке>" workspace/inputs/<код источника>
   ```

   Не используйте `rclone sync` и `move` в сторону облака.

**Сервисы встреч.** Агенту нужна дословная расшифровка с таймкодами и спикерами, а не сводка ИИ. Если коннектора к сервису встреч нет, выгрузите расшифровки в .txt или .docx в папку источника.

### Шаг 3. Проверка после дайджеста

В служебной части черновика, в разделе «Источники», агент пишет по каждому источнику число найденных и прочитанных файлов и список непрочитанных. Если число найденных меньше, чем в облаке, проверьте доступ к вложенным папкам и повторите.

## Как сменить ИИ

Правила, шаблон и настройки остаются прежними. Меняется только способ подключения: другой раздел этого файла или другие строки в `.env`.
